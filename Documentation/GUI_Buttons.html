MovementLogger — BLE FileSync button reference

Quick reference for the BLE FileSync panel in MovementLogger. Each button, what it does, when to use it, and what happens behind the scenes. May 2026.

Where to find it: Open MovementLogger, click BLE FileSync (download from PumpTsueri) to expand the panel. PIN is 123456 on first connect.

Connection lifecycle

ButtonEnabled whenWhat it does
Scan Disconnected (and not currently scanning) Starts a 5-second BLE scan. Any peripheral advertising as PumpTsueri appears under Discovered. Click the device row that appears to bring up the Connect button. Re-clicking Scan clears the previous results.
Connect After Scan found a device Pairs and connects to the box. macOS / Linux / Windows pops a Bluetooth permission dialog and a PIN dialog the first time — enter 123456. The OS remembers the pairing; subsequent connects skip the PIN. On success the file list auto-loads.
Disconnect Connected Cleanly tears down the BLE link (sends LL_TERMINATE_IND so the box can immediately accept the next host). The GUI returns to Idle state — Scan becomes available again. Box keeps advertising and is reachable within ~1 second.
Don't pkill -9 the GUI. A hard kill skips the graceful disconnect — the box's BLE link stays "occupied" until the supervision timeout (10–30 s on macOS), during which a fresh GUI launch can't connect. Close via Cmd-Q (red traffic light on macOS) for a clean exit, or simply Disconnect first.

File operations

ButtonEnabled whenWhat it does
Refresh file list Connected Sends OP_LIST (0x01) to the box. Each file on the SD root comes back as a row with its size. Rows are split into two groups:
  • Sensor — Sens*.csv, Gps*.csv, Bat*.csv, Mic*.wav. These are session data and default-ticked.
  • Debug — FW_INFO_vN.TXT, CHKNN.TXT, the Error_Log_Pump_Tsueri_*.log error log, plus any macOS AppleDouble files (._*). Default-unticked.
Each group header has a Tick all / Untick all toggle.
Download selected Connected, at least one row ticked and not yet downloaded Reads all ticked, not-yet-downloaded files one at a time (serial queue — the box can only stream one file at a time). The button shows Download selected (N queued) while running. Each row gets:
  • A live progress bar (1.23 / 5.00 MB) updating every ~4 KB received.
  • A green ✅ downloaded badge on completion.
Saved to the path in the Save to: field. Sens*.csv and *_gps.csv auto-fill the visualization form's top-level slots so you can hit Generate immediately. The same file can be re-downloaded by clicking Refresh file list first.
🗑 (per row) Connected, that row is not currently downloading Sends OP_DELETE (0x03) for that single file. On success (0x00 OK reply) the row vanishes from the list. Other replies surface in the Log panel: BUSY (logging in progress, send STOP_LOG first), NOT_FOUND, IO_ERROR. Be deliberate — there is no confirmation dialog.

Logging sessions

ButtonEnabled whenWhat it does
STOP_LOG Connected Sends OP_STOP_LOG (0x04). If a logging session is in progress on the box, this gracefully closes SensNNN.csv, GpsNNN.csv, etc. (so they're complete and downloadable). No reply from the box — the GUI logs STOP_LOG sent immediately. After a few seconds you can Refresh file list to see the closed files.
1800 s Connected Session duration in seconds (1–86400). Click and drag to scrub, or click and type. Drives the next Start session. Default is 1800 s (30 minutes). For short tests drop to 60 s.
Start session Connected Sends OP_START_LOG (0x05) plus the duration. The box writes a magic value to its backup register and immediately reboots into LOG mode (the BLE stack does not run in LOG mode — it's mutually exclusive with SD logging on this hardware). The BLE connection drops; the GUI flips to Idle. The box logs for the requested duration, then auto-reboots back into BLE mode and advertises PumpTsueri again.
While a session is running the GUI shows an amber banner above the action buttons: "Logging in progress — M min SS s left … Box is silent, won't appear in Scan." The countdown ticks every ~500 ms and clears itself automatically once the deadline expires (plus ~8 s for BLE bring-up). Once cleared, click Scan and the box reappears.
To abort a session early short-press the physical user button on the box. fx_thread sees the button event and closes the files cleanly; in some firmware versions the box also reboots back into BLE mode.

Sidebar elements

ElementWhat it does
Save to: Where downloads land on your computer. Defaults to ./csv/ relative to the GUI binary. Edit inline or click Browse… to pick a folder. The same path is used for every download in the session.
Log panel (bottom) Scrolling history of every BLE state transition: LIST sent, reading X (N B)…, saved /path/to/X, DELETE X sent, errors, etc. Fully selectable: click-drag to highlight, Cmd-A select all, Cmd-C copy. The Copy all button in the panel header dumps the whole buffer to the clipboard in one click.
Window size The Log panel grows vertically with the window — drag the bottom-right corner down to see more lines without scrolling.

Status bytes you might see in the Log

CodeMeaningWhat to do
0x00OKOperation succeeded. (For READ/DELETE you'll see the ✅ badge / row vanish.)
0xB0BUSYBox is currently logging — close files first with STOP_LOG, then retry.
0xE1NOT_FOUNDFile is in the LIST but the box can't open it. Usually FAT corruption on the SD card — pull the card, copy off what you need, reformat as FAT32.
0xE2IO_ERRORSame diagnosis as NOT_FOUND but on the write side (DELETE). Reformat the SD card.
0xE3BAD_REQUESTMalformed opcode or filename — bug in the GUI. Please report.

Typical workflow

1. Scan → wait 5 s → click discovered PumpTsueri → Connect (PIN 123456).
2. File list auto-loads. Adjust ticks if needed.
3. Download selected. Wait for ✅ badges.
4. To record more data: set 1800 s (or your preferred duration) → Start session. Watch the amber countdown banner. When it clears, the box is back.
5. Scan → Connect → Refresh file list → Download selected on the new SensNNN.csv row.
6. Disconnect when done, or just Cmd-Q the app (it'll Disconnect automatically).
